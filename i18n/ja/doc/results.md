# 結果

委託文には下記の書式を依頼元の言語で含め、指定保存先・レポート領域は指定ファイルだけ・完了通知不要・保存失敗時の扱いを伝えます。

```markdown
# 〈作業名〉
状態：〈作業中／完了／一部完了／要確認／中断〉
更新：〈日時・タイムゾーン〉

- 結果・成果物：〈何が変わったか、行った作業、成果物リンク〉
- 確認：〈成功・未実施・失敗、理由と未確認点〉
- 残事項：〈未解決事項や必要な判断。なければ省略〉
```

- 保存と提示はこの順序で、各項目1行程度にします。「完了」は依頼範囲と必須確認を満たした場合に使い、保存後に状態・未確認点・リンクを読み戻します。一緒に移動する成果物は相対リンク、他は表示先で開けるリンクにします。
- 保存先はユーザー指定を優先し、未指定なら委託元の `local/reports/<日付>-<作業名>.md` を一意に決めます。基準と実際のパス、または確認済み共有先を渡し、書き込み権限を確認します。
- 委託元は可能なら「作業中」の仮レポートを作り、`local/reports/README.md` にリンクを置きます。未作成は「作成予定」とし、レポートリンクにしません。共有一覧・台帳は委託元が更新します。
- 保存失敗時は許可された代替先か担当の最終回答に、理由・実際の保存先・結果を残します。結果を求められたとき、未作成・古い・保存先不明なら担当を確認し参照先を修正します。追加依頼は同じレポートの範囲・状態・日時を更新します。
- 送信成功後は「作業名 → 短い説明 → レポート → 担当チャットの別リンク」で案内し、一覧・結果閲覧も同じ並びにします。説明は確認済みの結果に合わせ、送信失敗・成否不明は明記します。
- 確認したIDとチャット名から `codex://threads/<thread-id>` を使います（[仕様](https://learn.chatgpt.com/docs/app/commands#deep-links)）。他の表示環境は対応確認済みのリンクだけを使い、未確認ならチャット名とリンク未確認の旨を示します。完了通知・公開共有は不要です。
