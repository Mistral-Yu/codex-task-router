# 结果

在委派消息中以请求者的语言附上下方格式，并说明指定保存位置、报告区域仅更新指定文件、无需完成通知及保存失败的处理。

```markdown
# 〈任务名称〉
状态：〈进行中／完成／部分完成／需要确认／已中断〉
更新：〈日期、时间及时区〉

- 结果与成果：〈发生的变化、实际工作及成果链接〉
- 验证：〈成功、未执行、失败，原因与不确定性〉
- 剩余事项：〈未解决事项或所需决定；没有时省略〉
```

- 保存与展示使用相同顺序，每项一行左右。仅满足请求范围及必要验证时标为“完成”；保存后重新读取状态、不确定性及链接。一起移动的成果使用相对链接，其他链接适配显示界面。
- 优先采用用户指定位置，否则在来源项目下选择唯一的 `local/reports/<日期>-<任务名>.md`。提供基准与实际路径或已核实的共享位置，并确认写入权限。
- 来源尽可能创建“进行中”占位报告，在 `local/reports/README.md` 放置链接。尚未创建时标为“计划创建”，不提供报告链接。共享目录和台账由来源更新。
- 保存失败时，在获准的替代位置或目标最终回复中保留原因、实际位置与结果。用户请求结果且报告未创建、过时或位置不明时，来源查看目标并修正引用。追加请求更新同一报告的范围、状态与时间。
- 确认送达后按“任务名 → 简短说明 → 报告 → 独立的负责会话链接”展示，目录与结果查看也用相同顺序。说明依据已确认结果更新，送达失败或未知时明确说明。
- 用已核实的 ID 和会话名称提供 `codex://threads/<thread-id>`（[规范](https://learn.chatgpt.com/docs/app/commands#deep-links)）。其他环境仅用已确认支持的链接，否则展示会话名称并标明链接未确认。无需完成通知或公开分享。
